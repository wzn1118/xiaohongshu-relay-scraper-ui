## 正文

找实习时最耗时间的，往往不是“看见岗位”，而是后面这一串重复动作：

复制岗位正文、整理职责和要求、翻简历找证据、改一版求职信，再回到原帖找邮箱或私信入口。

所以我做了一个 **小红书实习岗位 AI 求职助手**，把这条链路放进一个本地优先的工作台里：

- 发现岗位：按关键词采集公开岗位，并整理岗位正文、时间和投递方式

- 简历匹配：导入 PDF / DOCX / TXT 等资料，先识别候选人事实，再由你核对

- 定制文案：针对每条岗位生成私信、邮件和 Cover Letter，不是一份模板套全部岗位

- 质量评审：检查相关性、证据、表达和行动就绪度，低于门槛就进入重写

- 结果可导出：JSON、CSV、XLSX、Markdown 都能留下，方便复盘和归档

## 使用教程

### 1. 启动工作台

Windows 下载项目 ZIP，解压后双击根目录的 `start-windows.cmd`。首次启动会准备项目运行环境，页面打开后访问：

`http://127.0.0.1:4317`

### 2. 连接浏览器和小红书页面

在「Relay 配置」里保留默认端口，点击「一键安装并接入」；然后点击「打开小红书登录页」，在项目托管的浏览器里完成登录。

页面显示 Relay 已连接、并发现小红书标签页后，再进入下一步。

### 3. 连接 AI Runtime

在「模型连接与个人背景记忆」里选择本地模型，或填写 OpenAI 兼容服务的 Base URL、协议、模型和 API Key，点击「连接 AI」。

接着导入自己的简历，检查姓名、学校、专业、联系方式、每周可实习天数和预计实习时长。系统只会把简历和背景资料中明确存在的事实带入文案。

### 4. 创建采集任务

在「新建采集与投递分析任务」中填写关键词，例如：

`数据分析实习`、`产品实习`、`运营实习`

按需要选择「最新」和时间范围，确认浏览器 Profile、Relay 端口与采集节奏后，点击「启动全流程」。任务会依次完成岗位正文、时间、岗位能力、简历匹配、文案生成和质量评审。

### 5. 检查并编辑结果

在「逐链接岗位与投递文案」里查看岗位详情、职责、要求、投递方式和匹配依据，再编辑私信、邮件或 Cover Letter。通过质量门禁后，可复制私信、打开岗位或按本机 SMTP 配置发送邮件。

### 6. 导出和复盘

在「交付文件」区域下载 JSON、CSV、XLSX 或 Markdown。任务历史会保留采集状态、正文覆盖率、质量结果、失败原因和检查点，方便下一次从中断位置继续。

## 适合谁

适合准备数据分析、产品、运营、市场和内容实习的人，也适合想批量比较岗位，但不想牺牲文案个性化程度的人。

## 我特别保留的边界

它不会替你自动投递。岗位正文不完整、浏览器验证未完成或文案质量未达门槛时，任务会停下来并保留检查点；最终发送前，仍由你人工确认内容和收件地址。
