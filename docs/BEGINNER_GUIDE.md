# 小红书实习岗位 AI 求职助手：傻瓜式教程

这份教程只解决一件事：**第一次使用时，照着顺序点击，就能完成“启动 → 登录 → 连接 AI → 采集 → 查看 → 下载”**。

## 你最后会得到什么

一次任务完成后，可以在工作台里看到：

- 小红书公开岗位卡片、岗位正文、发布时间和来源链接
- 岗位职责、岗位要求、关键能力和投递方式
- 根据你的简历事实生成的私信、邮件和 Cover Letter 初稿
- 每条岗位的评分、问题和修改记录
- JSON、CSV、XLSX、Markdown 等可下载文件

系统不会自动替你投递。邮件必须由你主动点击“发送邮件”，私信需要你复制文案后打开原帖发送。

## 第 0 步：先准备好

第一次使用前准备下面 4 项：

1. 一台能联网的 Windows 电脑。Windows 一键启动会检查并准备 Node.js 22+、Python 3.11+、项目依赖和 Chrome/Edge；自动安装依赖需要系统有 `winget`。
2. 一个可以登录小红书的账号。登录只需要在这台电脑的项目浏览器里完成一次。
3. 一份自己的简历，支持 PDF、DOCX、TXT、Markdown、JSON、CSV、RTF。
4. 一种 AI 方式，二选一：
   - **本地免费模型**：需要本机安装 Ollama，文本留在本机，不需要 API Key。
   - **OpenAI 兼容服务**：需要服务商提供的 API Base URL、API Key 和模型名。

没有简历也能先试运行采集，但没有背景资料时，岗位匹配和求职信不会完整。

## 第 1 步：下载并启动

### Windows：最简单的方式

1. 打开项目的 [GitHub 仓库](https://github.com/wzn1118/xiaohongshu-relay-scraper-ui)。
2. 点击绿色的 **Code**，再点击 **Download ZIP**。
3. 把 ZIP 解压到一个容易找到的目录，例如 `D:\xiaohongshu-relay-scraper-ui`。
4. 打开解压后的项目文件夹，双击根目录的 `start-windows.cmd`。
5. 第一次启动会安装依赖、构建页面并准备浏览器，可能需要等待几分钟。看到启动窗口中的 `Application is ready` 后，浏览器会打开：

   ```text
   http://127.0.0.1:4317
   ```

6. 启动窗口不要关闭。关闭它会停止本地服务；下次再次双击同一个文件即可恢复使用。

如果浏览器没有自动打开，手动复制上面的地址到 Chrome 或 Edge 即可。

### Linux / macOS

需要先安装 Node.js 22+、Python 3.11+ 和 npm，然后在终端执行：

```bash
git clone https://github.com/wzn1118/xiaohongshu-relay-scraper-ui.git
cd xiaohongshu-relay-scraper-ui
chmod +x start-linux-macos.sh
./start-linux-macos.sh
```

页面地址仍然是 `http://127.0.0.1:4317`。如果提示缺少 Node.js 或 Python，先安装对应运行时，再重新执行启动脚本。

## 第 2 步：让浏览器登录小红书

启动后，先看页面上方的 **Relay 配置**。

### 正常情况

如果看到 **目标页已打开**，说明浏览器页面已经准备好，可以继续下一步。

### 需要登录的情况

按下面顺序操作：

1. 点击 **打开登录页**。如果页面只显示简化按钮，先点击 **手动连接向导**。
2. 在项目自动打开的独立浏览器窗口里完成小红书登录。
3. 回到工作台，等待 Relay 状态变成 **目标页已打开**。

默认配置是：

```text
Relay 端口：18800
浏览器 Profile：openclaw
```

第一次使用时不要修改这两个值。**看到“Relay 服务已启动”不等于已经登录**，还要确认状态显示“目标页已打开”。登录状态保存在本机的项目浏览器 Profile 中，不会同步到 GitHub。

如果 Relay 还是待配置，可以点击 **一键安装并接入**，等待准备完成后再点击 **打开小红书登录页**。

## 第 3 步：连接 AI

在页面找到 **模型连接与个人背景记忆**，先完成 AI 连接。

### 方案 A：本地免费模型，适合第一次使用

1. 在 **AI Runtime** 的提供方中选择 **本地免费模型库**。
2. 如果页面提示没有本地运行器，点击 **安装本地运行器**，按打开的官方页面完成 Ollama 安装。
3. 回到工作台，选择一个推荐模型，例如 `qwen3.5:4b`。
4. 点击 **一键安装**，等待模型下载完成。模型较大时需要等待更久。
5. 下载完成后点击 **启用模型**，再点击 **连接 AI**。
6. 看到 AI 会话已连接后，继续下一步。

本地模型的速度取决于电脑 CPU、GPU 和内存。第一次测试建议使用“限定数量”而不是“全量发现”。

### 方案 B：OpenAI 兼容服务

1. 提供方选择 **API 中转站（OpenAI 兼容）**。
2. 填写服务商提供的 **API Base URL**，例如 `https://gateway.example/v1`。
3. 粘贴 **API Key**。
4. 根据服务商文档选择协议：`Chat Completions` 或 `Responses API`。
5. 点击 **检测模型**。
6. 从检测到的列表中选择模型。
7. 点击 **验证并连接**。

API Key 只保存在当前设备的本地运行时配置中，不要把它粘贴到 README、Issue 或 Git 提交里。

## 第 4 步：导入简历和个人资料

仍然在 **模型连接与个人背景记忆** 区域：

1. 点击 **选择多格式背景文件**，选择简历文件。可以同时选择多份文件，例如简历、项目说明和作品集文字版。
2. 如果有额外信息，可以在文本框里补充，但只填写真实、可核对的内容。
3. 点击 **解析并写入记忆**。
4. 在 **选择背景记忆** 下拉框里选中刚刚生成的个人档案。
5. 检查 **求职信署名信息**：姓名、学校、专业、年级/学历、电话/微信、邮箱、每周可实习天数、预计实习时长。
6. 如果系统从简历自动识别了信息，逐项核对；识别错误的字段直接手动修改。

不要为了让文案更好看而填写简历中不存在的经历、数字、公司或联系方式。系统会尽量只使用已经提供的事实。

## 第 5 步：创建第一次采集任务

在页面的 **新建采集与投递分析任务** 区域按下面填写：

1. **搜索关键词**：输入一个明确关键词，例如 `产品运营实习`、`数据分析实习`。
2. **采集范围**：选择 **限定数量**。
3. **采集上限**：第一次填 `5` 或 `10`。
4. **浏览器 Profile**：保持 `openclaw（独立）`。
5. **Relay 端口**：保持 `18800`。
6. **帖子时间范围**：第一次可以保持默认的 **近 30 天**。
7. **采集节奏**：保持默认设置；不需要修改高级参数。
8. 先点击 **仅检查链路**。检查通过后，再点击 **启动全流程**。

项目会固定按 **最新发布** 采集。任务启动后不要频繁重复点击启动按钮，先观察 **当前任务** 和 **运行日志**。

## 第 6 步：等待并判断结果

任务运行时重点看 3 个位置：

- **当前任务**：看任务状态和进度。
- **运行日志**：看当前执行到了哪个阶段。
- **结果覆盖与事实边界**：看发现了多少岗位、完成了多少正文、是否通过质量门禁。

正常结束时，任务状态会显示 **任务已完成**。如果出现下面情况，不要把它当成完整结果：

- **信息未完整**：某些岗位只有卡片信息，正文还没有拿到。
- **等待人工完成安全验证**：需要在托管浏览器中完成登录或页面验证。
- **任务未完成 / 检查点已保留**：当前结果可以继续，但流程还没有走完。

### 遇到安全验证怎么办

1. 点击 **打开验证页** 或 **打开小红书检查页**。
2. 在托管浏览器中完成页面要求的登录或验证。
3. 回到工作台，点击 **我已完成验证，刷新状态**。
4. 如果任务已经停下，点击 **我已完成验证，刷新并继续** 或 **从检查点续跑**。

### 某些岗位正文缺失怎么办

在结果区域点击 **一键智能补全**。系统会使用已经保存的检查点，只处理缺失内容。补全结束前，不要把缺失正文的岗位当作已经核验的岗位。

## 第 7 步：查看和修改求职文案

在 **逐链接岗位与投递文案** 区域：

1. 点击左侧的岗位卡。
2. 查看岗位职责、岗位要求、关键能力、投递方式、采集正文和岗位图片。
3. 查看右侧的 **私信文案**、**邮件文案** 和 **专属 Cover Letter**。
4. 需要修改时直接编辑文本框。
5. 修改后点击 **保存修改**。
6. 私信可以点击复制按钮，然后打开岗位原链接手动发送。

页面会显示用人单位评分。通常只有评分达到 `90 / 100` 且岗位正文中存在可验证邮箱时，邮件发送按钮才会启用。

## 第 8 步：配置邮箱并发送邮件（可选）

如果只想复制私信或下载文案，可以跳过这一步。

需要发送邮件时：

1. 找到页面的 **发件邮箱**。
2. 填写自己的发件邮箱。
3. 网易、QQ 等邮箱填写 **客户端授权密码 / 授权码**，不是网页登录密码。
4. 点击 **配置并测试**。
5. 看到 **连接已验证** 后，再回到岗位详情。
6. 确认收件人、主题和正文无误，点击 **发送邮件**。

系统不会自动批量发送；每次发送都需要你确认当前岗位和当前文案。

## 第 9 步：下载结果

1. 滚动到页面下方的 **交付产物**。
2. 先在 **任务记录** 中点击目标任务，确保当前任务是你刚刚运行的那一个。
3. 在交付产物列表中点击文件名或右侧下载图标。
4. 根据用途选择文件：
   - `JSON`：保留完整结构，适合后续程序处理。
   - `CSV`：适合用 Excel 快速筛选。
   - `XLSX`：适合直接查看和整理。
   - `Markdown`：适合阅读和复制文案。

文件通常来自任务目录下的：

```text
data/jobs/<JOB_ID>/artifacts/
```

## 第 10 步：下次怎么继续使用

下次使用只需要：

1. 双击 `start-windows.cmd`，或执行 `./start-linux-macos.sh`。
2. 打开 `http://127.0.0.1:4317`。
3. 检查 Relay 是否显示 **目标页已打开**。
4. 检查 AI 是否显示已连接。
5. 选择已有的背景记忆，填写新关键词，启动新任务。

不要删除 `data/browser`、`data/profiles`、`data/ai-config.json`，否则可能需要重新登录、重新导入背景资料或重新连接 AI。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 页面打不开 | 保留启动窗口，确认访问 `http://127.0.0.1:4317`；也可以运行 `start-windows.cmd -CheckOnly -NoBrowser` 检查环境。 |
| 端口被占用 | 关闭占用该端口的旧实例，或在 `.env` 中修改 `PORT`，然后重新启动。 |
| Relay 已启动但目标页未打开 | 点击 **打开登录页**，在项目浏览器中完成登录，等待状态变成 **目标页已打开**。 |
| AI 检测不到模型 | 检查 Base URL、API Key 和协议；常见 Base URL 是服务商的 API 根地址或 `/v1` 地址。 |
| 采集结果不完整 | 确认浏览器已登录，再点击 **一键智能补全** 或从检查点续跑。 |
| 邮件按钮不能点 | 先确认岗位有可验证邮箱、文案评分达到 90，并在 **发件邮箱** 中完成配置并测试。 |
| 第二台电脑没有登录状态 | 这是正常的。登录 Cookie 只保存在原电脑，需在新电脑的项目浏览器中重新登录。 |

## 不要提交到 GitHub 的内容

下面内容属于本机数据，不要上传：

- `.env`
- `data/ai-config.json`、SMTP 配置和任何 API Key
- `data/browser` 中的浏览器登录状态
- `data/profiles` 中的个人简历和背景资料
- `data/jobs` 中的岗位记录、联系方式和导出结果

这些目录默认在 Git 忽略范围内。提交代码前可以运行：

```powershell
git status --short
```

确认没有把个人资料、密钥或任务数据列在待提交文件中。
