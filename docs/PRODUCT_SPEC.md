# v3 产品规格

## 成功定义

一次正式任务只有同时满足以下条件才算成功：

- 所有发现的可访问文章均保存完整正文，或安全验证等待 10 分钟后明确转入部分分析。
- 每条正文均输出职责、要求、具体日期、投递方式和核心能力。
- 每条可分析记录都有独立的第一人称私信、邮件与 Cover Letter。
- 用人单位评审分数达到用户阈值，产品默认且最低为 90 分。
- 工作流摘要、结构化文件和 SHA-256 清单存在且可解析。

启动进程、Relay 在线、仅采集卡片摘要、生成固定 20 条或 AI 只返回草稿都不代表成功。

## 核心流程

1. 用户在 UI 选择 OpenAI、Codex、DeepSeek、Qwen 或自定义兼容服务并配置会话。
2. 用户上传 PDF、DOCX、TXT、Markdown、JSON、CSV 或 RTF，也可补充背景文本。
3. Background Memory Agent 生成仅含材料支持事实的本地记忆。
4. 用户开始全量采集或从历史检查点续采。
5. 系统保存正文及 `scraped_at`，标准化相对时间并提炼岗位信息。
6. Writer Agent 直接展示能力相符的行动、协作和结果，不提材料来源，不复述招聘正文。
7. Employer Review Agent 严格评分；低于阈值最多重写 6 次，默认 4 次。
8. 达标后 UI 启用“准备投递”和“准备私聊”。按钮复制对应文案并保存处理状态，不自动发送。

## 数据与隐私

- API Key 仅驻留服务进程内存，8 小时过期。
- Relay Token 每次从本机 OpenClaw 配置读取，只用于派生本地鉴权，不进入页面响应。
- `.env`、上传文件、背景记忆、任务数据、日志和个人证据均不得提交 Git。
- AI 输出必须引用存在的 evidence id；不得编造公司、成果、技能、联系方式或数字。

## 界面

- 顶部设置区：Provider、Key、Base URL、模型、文件上传、背景文本和已保存记忆。
- 任务控制区：关键词、浏览器 Profile、全新/续采、Relay 端口、正文与安全验证参数。
- Agent 轨道：8 阶段实时状态、数量与日志。
- 结果区：岗位职责、要求、具体日期、投递方式、能力、文案、评分、重写次数和处理按钮。
- 历史与产物区：任务状态、覆盖率、错误原因、JSON/CSV/XLSX/manifest 下载。

## 兼容性

- Node.js 22+，Python 3.11+。
- Windows 为主要浏览器 Relay 环境；应用构建、AI 处理和历史查看同时支持 Linux/macOS。
- 上游 Skill 允许位于 `CODEX_HOME` 或通过 `.env` 提供绝对路径。
