# 30/60/90 秒项目口述

## 30 秒：主项目

我做的是一个本地优先的小红书 Relay 数据工作台。React/Vite 负责配置和结果编辑，Node 负责任务、SSE、权限和外部动作，Python 负责浏览器采集、OCR 和分析。核心不是单次抓取，而是用 checkpoint、event journal 和 ledger 做可恢复任务，再把来源绑定到 AI 生成的结构化草稿，经过确定性质量门和人工确认后交付。

## 60 秒：主项目

用户可以在受管浏览器中发现岗位或内容，系统补全正文、评论和用户关系，形成带来源的结构化记录。Node 创建 job/attempt，Python 运行八阶段工作流，事件写入 JSONL 并通过 SSE 展示。进程退出或遇到安全验证时，系统暂停 gate，保留 checkpoint 和部分产物，恢复时按 ledger 跳过已确认工作。AI 部分使用 evidence id、source span、JSON schema、独立审阅和确定性 validator，低质量结果停留在草稿层。批量投递还需要 dry-run、freeze、approve、send 和 receipt。Data Copilot/MCP 则在 snapshot、manifest、grant 和 approval 约束下做分析和工具调用。

## 90 秒：主项目 + 取舍

这个项目的核心问题是：浏览器、模型和邮件都是不稳定且可能有副作用的外部边界，怎样把它们变成用户可理解、可恢复、可审计的本地产品。我们用 React/Vite 做交互，用 Node 原生 HTTP 和 JobManager 管理状态，用 Python 处理 Playwright、OCR、表格和报告。任务有 job、attempt、revision、checkpoint、ledger、event journal 和 artifact manifest；SSE 支持 sequence 与 Last-Event-ID 回放。AI 不是直接输出自由文本，而是先绑定 evidence，再由 schema、validator、独立 review 和人工确认控制质量。JSON 文件适合用户看见和复制，SQLite WAL 适合 Copilot/MCP 的租约、幂等和事务，所以两者并存并用 snapshot/hash 关联。当前最大问题是大文件、双存储复杂度和未提交 Codex runtime 扩展，下一步是边界拆分、跨语言契约、性能基准和安全回归。

## 30 秒：Asteria

Asteria Analyst 是企业数据分析和管理报告工作台。它把字段画像、AI 语义映射、业务路由和指标计划与确定性统计执行、证据校验和正式 PDF 发行门分开。最适合讲“模型提议、代码计算、证据绑定”的可信分析链。方法数量和报告质量数字要按 README/代码快照等级表述。

## 30 秒：Hegel Salon

Hegel Salon 是中文哲学阅读与推理工作台。它用本地语料、概念图、历史参照和引用校验支持问答，并通过质量/逻辑/史学判官和多轮修订暴露问题。最适合讲 RAG 的引用纪律、上下文边界、多用户隔离和评测，不把模型分数说成学术证明。

## 30 秒：KOLFORGE

KOLFORGE 是多平台 KOL 发现和建联工作台。connector 将不同平台的账号和内容归一化，checkpoint 和受限并发支撑长任务，ASR/OCR/评论证据进入七代理营销报告，最后生成可审计的个性化消息。它是本地未版本化快照，规模数字和质量指标需要补证。

## 30 秒：便携交付

today-you-applied-portable 是主项目的 Windows 便携交付章节。重点是把 Node、Python、浏览器和配置做成首次启动、健康检查、净化和 rollback 都可验证的 package。包内的岗位/评论/用户数字只是数据快照，不是业务指标。

## 面试收尾

我会把下一步放在三件事：先按 bounded context 拆大文件并保持契约兼容；再补跨 Node/Python 的 contract test、外部故障注入和性能基准；最后把工作区 Codex 扩展单独收敛为有版本、有权限模型、有回滚的发布模块。
