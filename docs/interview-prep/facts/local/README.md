## 1. 使用方式

这组文档用于给 GPT 提供面试背景事实，而不是直接充当简历。回答时应先选择与问题有关的事实，再组织成“背景、任务、行动、结果、反思”。

建议按以下顺序提供给 GPT：

1. 本索引，说明事实等级和项目归属边界。
2. 对应项目的完整事实文件。
3. 主面试包中的项目卡片、STAR 故事或问答文件。
4. 要求 GPT 对每个数字标注来源等级，不把文档声明改写成当期实测。

## 4. 归属边界

- `MKT大师`、`today-you-applied-portable` 和 `Playground` 均有 `.git`，但都没有任何提交和远端，因此本机内容的演进过程、作者贡献比例和公开发布时间缺少 Git 证据（F2/F5）。
- `today-you-applied-portable` 与当前主仓库共享大量架构、命名和业务链路，应表述为主项目的便携产品化/发布快照，不宜包装成完全独立的第四个原创产品（F1/F5）。
- `MKT大师` 同时包含 KOL 工作台、三国杀 WUHU 营销报告脚本、Codex 会话取证与能力编译器。面试时要明确本次问题谈的是哪条能力线（F1）。
- `Playground` 的三个子目录都没有嵌套 `.git`；它们共享父目录的空 Git 元数据，适合作为原型或工程练习，不具备独立版本历史（F2）。
- `Playground 2` 和 `Playground 3` 没有业务文件；`本电脑` 的 README 是个人主页内容，迁移脚本是系统工具。三者不列为产品项目（F1/F2）。

## 5. 数字使用约束

- 文件数、行数、目录大小：均为 2026-08-18 本地快照，可用于说明复杂度，但不等于有效代码量、生产规模或个人独立贡献。
- 测试文件数：表示测试资产存在；只有明确的运行日志或状态文件才属于运行证据。
- README 中的数据量、用户反馈和业务结果：保留为 F3，除非另有原始数据或验收产物支持。
- 本地 `output`、`data`、SQLite 和截图：保留为 F4；它们可能来自不同版本和不同日期，不应拼接成同一次完整验收。
- 没有提交历史的目录：项目归属与个人贡献应由原始对话、设计稿、运行记录或公开仓库补证。

## 6. 快速项目地图

### KOLFORGE / MKT大师

- React/Vite 单页工作台 + Node ESM API + Python/Node 采集与分析脚本。
- 覆盖小红书、抖音、B 站，支持 Browser Relay、开放平台/合作方边界、内容与视频证据、外联草稿和报告。
- 另含 106 文件的会话取证/能力编译子系统，以及 31 个 WUHU 营销分析脚本。
- 869 个 Git 可见文件中有 565 个位于 `tmp`；`output` 当前约 13.55 GiB，运行产物与源码混放风险明显。

### 今天你投了吗？便携版

- 清单版本 `3.1.7`，React 19 + TypeScript + Vite 6 + Node API + Python 工作流。
- 27 个 npm 脚本、153 个非测试源码文件、103 个测试代码文件。
- 当前工作区已有 Playwright `passed` 状态文件，但本次盘点没有重新执行测试。
- README 声明发布包包含 715 条岗位及研究数据；本地 `data` 目录当前只看见 2 个小型工作流文件，两者属于不同证据口径。

### Playground

- 飞书机器人：FastAPI、Responses API、`previous_response_id`、SQLite 去重与会话指针。
- 外接显示器亮度控件：PowerShell + WinForms + DDC/CI + Win32 P/Invoke + 单实例与开机启动。
- Relay 采集器：Playwright/CDP、卡片缓存、断点恢复、JSON/CSV/XLSX 和结构化投递表。
