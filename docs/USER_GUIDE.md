# APP Relay Scraper UI 傻瓜式使用教程

> 本教程面向第一次使用的人，按“看到什么就点什么”的顺序说明每一步。教程覆盖启动、Relay 连接、登录、AI、背景资料、候选人信息、采集任务、运行监控、异常恢复、结果查看、文案修改、邮件发送、历史记录和产物下载。

## 0. 先看懂整条流程

完整流程只有 10 个阶段：

1. 准备运行环境。
2. 启动网页控制台。
3. 连接本机 Relay 和浏览器标签页。
4. 在 APP 登录一次。
5. 连接 AI 或安装本地模型。
6. 填写背景资料和候选人资料。
7. 配置采集关键词、范围、速度和高级参数。
8. 先做链路检查，再启动全流程。
9. 处理登录验证、限流或失败任务，并从检查点继续。
10. 查看结果、修改草稿、通过质量门禁后发送邮件或复制私信。

第一次使用建议完整走一遍。后续使用通常只需要：启动控制台 -> 连接浏览器 -> 确认 AI 和候选人资料 -> 填关键词 -> 检查链路 -> 启动任务。

## 1. 使用前准备

### 1.1 你需要准备什么

- Windows 电脑；Linux/macOS 也可以使用命令行启动方式。
- 可用的 Node.js、npm、Python 和 Chrome/Edge 浏览器。
- APP 账号，并能在浏览器中正常打开目标页面。
- 一种 AI：本地模型，或一个可用的远程 API。
- 如果需要发送邮件：发件邮箱和 SMTP 密码、客户端授权码或 OAuth2 信息。
- 如果需要生成个性化文案：候选人姓名、学校、专业、邮箱等基本资料。

### 1.2 目录中的重要位置

| 位置 | 用途 |
| --- | --- |
| `src/` | 前端页面和交互代码 |
| `server/` | 本地 API、任务调度和 Relay 连接 |
| `scripts/` | 启动、环境检查、产物验证脚本 |
| `data/` | 本地浏览器数据、任务状态、检查点和运行产物 |
| `artifacts/` | 可下载的 JSON、CSV、XLSX 和汇总文件 |
| `docs/` | 使用说明和设计说明 |

不要删除 `data/` 中的浏览器数据，否则可能需要重新登录。不要把 `data/`、`.env`、API Key、邮箱密码或 OAuth2 Refresh Token 提交到公开仓库。

## 2. 第一次启动

### 2.1 Windows 一键启动

1. 打开项目根目录。
2. 双击 `start-windows.cmd`。
3. 等待命令窗口完成环境检查和服务启动。
4. 打开浏览器访问 `http://127.0.0.1:4317`。
5. 页面能看到“控制台”以及 Relay 状态卡片，说明网页控制台已经打开。
6. 启动后的命令窗口不要关闭。关闭它会停止本地服务。

一键脚本会检查或准备 Node.js、Python、浏览器、依赖和本机 CDP 服务。第一次启动时间可能较长；只要命令窗口仍在运行，就先等待，不要连续双击多个启动脚本。

### 2.2 手动启动

在项目根目录打开 PowerShell：

```powershell
npm install
npm run dev
```

然后访问：

```text
http://127.0.0.1:4317
```

如果只启动后端：

```powershell
npm run start
```

### 2.3 启动后先看哪里

页面顶部有四类 Relay 状态：

- `Relay 已连接`：本地服务、CDP 和目标标签页都已准备好。
- `Relay 已启动，待登录`：浏览器已打开，但还没有确认登录状态。
- `Relay 连接中`：正在检查或建立连接，请等待几秒。
- `Relay 待配置`：端口、Profile 或服务尚未配置。

顶部还会显示 CDP 端口、当前标签页数量、刷新按钮和北京时间。看到端口通常是 `18800`，说明使用的是默认 Relay 端口。

### 2.4 顶部导航和通知

- **控制台**：回到任务配置、运行状态和结果区域。
- **历史**：跳到历史任务列表。
- **产物**：跳到当前任务的下载文件列表。
- **设置**：跳到发件邮箱和其他配置区域。
- 页面顶部出现提示条时，阅读完内容后可以点击关闭按钮隐藏提示；关闭提示不会删除任务或配置。
- 顶部 Relay 刷新按钮会通过代码重新检查连接；连接异常时先点它，再决定是否重新启动服务。
- 顶部北京时间用于对照任务创建时间、发布时间和日志时间。

## 3. 第一步：连接 Relay 和浏览器

找到“Relay 连接”卡片。第一次使用时，严格按下面顺序操作。

### 3.1 填写连接参数

1. 在“Relay 端口”填写端口，默认值是 `18800`。
2. 端口必须在 `1024` 到 `65535` 之间。
3. 在“浏览器 Profile”填写或保留 `openclaw`。
4. 如果希望每次打开控制台自动连接，打开“开机自动连接”。
5. 点击“检测连接”。

如果检测成功，状态会进入“Relay 已连接”或“Relay 已启动，待登录”。如果服务尚未运行，页面会显示“保存并启动 Relay”，点击它即可启动。

### 3.2 使用手动连接向导

打开“手动连接向导”后，会看到四步：

1. **连接参数**：确认端口和 Profile。
2. **Relay 服务**：启动或检查本机 Relay。
3. **浏览器标签页**：确认浏览器已打开，并且能看到目标标签页。
4. **目标页面**：确认标签页已经进入 APP 的目标页面。

每一步完成后再继续下一步。页面中的“打开登录页”用于打开登录页面；“再开一个目标页”用于在已有登录页之外，再打开一个采集用标签页。

### 3.3 自动准备本机环境

如果页面提示依赖或浏览器环境未准备好：

1. 点击“自动准备本机环境”。
2. 等待依赖检查完成。
3. 看到成功提示后，再点击“检测连接”。

如果已经有 Relay 服务但页面没有识别：

1. 点击“保存并连接”。
2. 等待顶部状态刷新。
3. 仍无连接时，点击“打开登录页”。

“一键安装并接入”会把环境准备、Relay 启动和浏览器接入串成一个操作，适合第一次使用。执行期间不要关闭页面或命令窗口。

### 3.4 登录 APP

1. 点击“打开登录页”。
2. 在打开的浏览器标签页中完成登录。
3. 如果出现二维码、短信、设备确认或安全验证，按页面要求完成。
4. 登录完成后回到控制台。
5. 点击“检测连接”，或等待自动检测。
6. 顶部状态显示已连接，且标签页数量大于 0，才继续下一步。

登录凭据和浏览器会话保存在本机的浏览器数据目录中。后续只要不删除该目录，通常不需要每次重新登录。

### 3.5 Relay 连接失败怎么办

- **端口被占用**：换一个未占用的端口，例如 `18801`，同时确保启动脚本和控制台使用同一个端口。
- **服务未响应**：点击“保存并启动 Relay”，等待命令窗口出现服务启动信息。
- **没有目标标签页**：先点击“打开登录页”或“再开一个目标页”，再检测。
- **状态显示已启动但不是已连接**：完成登录，确认目标页面已打开。
- **浏览器不是预期 Profile**：检查 Profile 名称，重新启动并重新连接。
- **本机环境未准备**：点击“自动准备本机环境”，完成后重新检测。

## 4. 第二步：连接 AI

找到“AI 与后台”卡片。AI 是启动完整任务的前置条件；“仅检查链路”也会检查 AI 状态。

### 4.1 选择本地模型

本地模型不需要填写远程 API Key，也不会产生按调用计费。

1. 在“本地模型”区域查看模型目录。
2. 选择一个模型。
3. 点击“一键安装”。
4. 等待安装进度完成。
5. 安装完成后点击“启用模型”。
6. 确认页面显示本地 AI 已连接。

如果目录中没有合适的模型：

1. 在扩展模型输入框填写模型 ID，例如 `qwen3-vl:4b`。
2. 点击“安装扩展”。
3. 等待下载、安装和健康检查完成。
4. 回到模型列表，选择并启用它。

安装过程中可以看到轮询状态。不要在进度未结束时重复点击安装按钮。

### 4.2 连接远程 AI

如果使用远程服务，按顺序填写：

1. 选择“服务商”。
2. 填写“API Base URL”。有些服务要求填写到 `/chat/completions`，按服务商实际要求填写。
3. 填写“API Key”。
4. 选择协议：`Responses API` 或 `Chat Completions`。
5. 点击“检测模型”。
6. 在模型列表中选择模型；如果列表没有目标模型，选择自定义模型 ID 并填写模型名。
7. 点击“验证并连接”。
8. 看到连接成功后，再继续配置背景资料。

页面可能把“验证并连接”显示为“重新验证并连接”或“连接 AI”，含义都是保存配置并执行一次连接检查。

### 4.3 AI 配置检查

启动任务前，AI 状态应满足：

- 有一个已启用的本地模型，或远程模型已验证。
- 页面显示 AI 会话可用。
- 模型检测没有报错。
- API Key 没有被复制到日志、截图或提交文件中。

如果重启后 AI 仍显示已连接，说明保存的会话已被自动恢复。若会话失效，重新点击“检测模型”和“验证并连接”。

## 5. 第三步：导入背景资料和记忆

背景资料用于让 AI 了解公司、岗位、项目、技能或写作约束。没有背景资料也可以做部分采集，但完整文案和评分会缺少上下文。

### 5.1 上传文件

1. 在背景资料区域点击文件选择框。
2. 可一次选择多个文件。
3. 支持的格式：`.pdf`、`.docx`、`.txt`、`.md`、`.json`、`.csv`、`.rtf`。
4. 等待文件解析完成。

文件内容会被提取为文本并写入本地记忆，不会修改原文件。扫描版 PDF 如果没有可识别文字，解析结果可能为空。

### 5.2 填写补充文字

在背景文字输入框补充文件中没有写明的内容，例如：

- 业务介绍。
- 岗位重点。
- 不能编造的事实边界。
- 文案语气和格式要求。
- 联系方式或投递约束。

### 5.3 写入记忆

1. 可选择一个已有的保存档案。
2. 点击“解析并写入记忆”。
3. 等待页面显示解析摘要和技能标签。
4. 展开预览，检查关键信息是否正确。

不要把密码、Token、身份证号或其他不必要的敏感信息放入背景资料。AI 只应使用真实资料，缺失内容会在结果中标注，不应自行补写为事实。

## 6. 第四步：填写候选人资料

候选人资料用于生成投递信息和邮件签名。页面字段如下：

| 字段 | 是否必须 | 填写示例 |
| --- | --- | --- |
| 姓名 | 必须 | 张三 |
| 学校 | 必须 | 某某大学 |
| 专业 | 必须 | 计算机科学与技术 |
| 年级/学历 | 可选 | 2026 届本科 |
| 电话/微信 | 可选 | 仅在确实需要时填写 |
| 邮箱 | 必须 | name@example.com |
| 每周可实习天数 | 可选 | 4 天 |
| 预计实习时长 | 可选 | 3 个月 |

填写后检查：

1. 姓名、学校、专业、邮箱不能为空。
2. 邮箱格式正确。
3. 联系方式和实习时间是本人真实信息。
4. 切换页面或刷新后，资料仍能显示。

资料保存在浏览器本地存储中。要换候选人时，先清空并重新填写，不要把上一位候选人的资料留在当前任务里。

## 7. 第五步：配置发件邮箱

只有需要发送邮件时才必须配置邮箱。采集、分析、复制私信不依赖 SMTP。

### 7.1 简单配置

1. 找到“发件邮箱”。
2. 填写发件邮箱地址。
3. 填写邮箱密码或客户端授权码。
4. 点击“自动配置”。
5. 页面会根据域名尝试识别 SMTP 主机、端口和加密方式。
6. 点击“配置并测试”。

页面会自动识别常见邮箱域名，并显示 SMTP 主机、端口、SSL/TLS 或 STARTTLS 状态。

### 7.2 企业邮箱或高级配置

打开“企业邮箱 / 高级设置”，按实际邮箱服务填写：

- Provider：服务类型。
- Auth：`login`、`oauth2` 或 `none`。
- SMTP Host：SMTP 主机。
- Port：SMTP 端口。
- User：登录用户名。
- SSL/TLS：服务商要求直接加密时打开。
- STARTTLS：服务商要求升级连接时打开。

使用 OAuth2 时继续填写：

- Tenant。
- Client ID。
- Client Secret，可选。
- Refresh Token。
- Scope。

不要同时打开互斥的加密方式。端口、SSL/TLS 和 STARTTLS 以邮箱服务商的实际要求为准。

### 7.3 常见邮箱向导

页面内置 163/126/yeah 和 QQ/Foxmail 的操作向导：

**163/126/yeah：**

1. 打开“设置 -> POP3/SMTP/IMAP”。
2. 开启所需服务。
3. 创建客户端授权密码。
4. 把授权密码填入控制台，而不是网页登录密码。
5. 回到控制台，点击测试。

**QQ/Foxmail：**

1. 打开“设置 -> 账号与安全 -> 安全设置”。
2. 开启 POP3/IMAP/SMTP。
3. 生成 16 位授权码。
4. 把授权码填入控制台。
5. 点击“保存并测试”。

### 7.4 邮箱按钮和状态

- “清除配置”：删除本地保存的 SMTP 配置。
- “保存配置”：只保存，不发送测试邮件。
- “保存并测试”：保存并验证 SMTP 登录。
- “自动配置”：根据邮箱域名填充常见参数。
- 测试失败：先检查授权码、主机、端口、SSL/TLS 和防火墙。

发送按钮只有在以下条件全部满足时才会启用：AI 文案评分达到 `90` 分、结果中有有效收件邮箱、SMTP 配置已通过测试。

## 8. 第六步：配置采集任务

找到“任务配置”卡片。建议第一次只修改关键词和数量，其他参数先用默认值。

### 8.1 基本字段

1. **关键词**：填写要搜索的关键词，不能为空。
2. **采集范围**：
   - `全量发现`：持续发现符合条件的内容。
   - `限定数量`：输入数量，默认 `100`，最大 `1000`。
3. **浏览器 Profile**：
   - `openclaw（独立）`：使用项目管理的独立浏览器。
   - `chrome（当前浏览器）`：使用当前浏览器会话。
4. **Relay 端口**：必须和 Relay 连接卡片中的端口一致。

### 8.2 时间范围

可选择：

- `近7天`。
- `近30天`，默认值。
- `近90天`。
- `不限时间`。

无法识别日期的内容不会被静默丢弃，会保留并标记为未知日期，之后可以在结果区单独筛选。

### 8.3 排序规则

新任务会自动点击并确认“最新”排序。恢复任务也使用最新排序。旧的综合缓存不会直接当成新任务结果使用，避免把过期内容混入本次采集。

### 8.4 速度设置

有两种方式：

- **匀速**：使用固定间隔。
- **随机节奏**：填写最小秒数和最大秒数，例如 `0.8` 到 `2.4`。

随机节奏必须满足最小值小于或等于最大值。数值错误时，任务不能启动。

### 8.5 高级设置

打开“高级设置”后可以调整：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 最大滚动 | 60 | 单个结果页最多滚动次数，范围 1-100 |
| 稳定轮次 | 8 | 连续多少轮没有新内容后认为页面稳定，范围 1-20 |
| 页面超时 | 30000 ms | 页面操作等待时间，范围 1000-120000 |
| 安全验证等待 | 600 s | 等待人工完成验证的最长时间，范围 60-3600 |
| Codex 单批数量 | 8 | 每批交给运行时处理的数量，范围 1-20 |

还有三个开关：

- **AI 文案与评分**：逐条写作、评分，并在不达标时自动重写。
- **禁用自动附加**：保持当前浏览器会话，不自动附加新的浏览器。
- **跳过结构化导出**：只保留原始抓取结果，不生成结构化导出文件。

第一次使用不建议同时修改多个高级参数。改完参数后先点“仅检查链路”。

## 9. 第七步：检查并启动任务

### 9.1 看准备状态

任务配置底部有准备状态条，会检查：

- AI 会话。
- 背景记忆。
- 候选人资料。
- 搜索关键词。

缺什么会直接列出。先补齐缺项，再开始任务。

### 9.2 仅检查链路

1. 点击“仅检查链路”。
2. 等待检查完成。
3. 检查 Relay、浏览器、APP 页面、AI、背景记忆、候选人资料和参数验证结果。
4. 有失败项时，按页面给出的模块回去修正。

这一步不会执行完整采集，适合第一次运行或修改配置后确认环境。

### 9.3 启动全流程

1. 确认关键词、采集范围、时间和速度。
2. 确认 AI 会话可用。
3. 确认候选人必填资料完整。
4. 点击“启动全流程”。
5. 等待任务状态从“待开始”变成“进行中”。

启动按钮会在必填条件不满足时禁用。不要通过刷新页面绕过禁用状态，应先补齐缺失配置。

## 10. 第八步：查看运行过程

任务面板会显示状态、进度、实时计数和 8 个处理阶段。

### 10.1 8 个处理阶段

1. **全量正文 Agent**：获取并整理正文。
2. **时间归一化 Agent**：统一日期格式并标记未知日期。
3. **背景记忆 Agent**：将背景资料与结果关联。
4. **投递信息 Agent**：提取邮箱、私信、链接等投递方式。
5. **岗位能力 Agent**：提取岗位职责、要求和关键能力。
6. **AI 写作 Agent**：生成私信、邮件和求职信草稿。
7. **用人单位评分 Agent**：按质量标准评分。
8. **质量门禁 Agent**：检查是否达到发送或交付条件。

### 10.2 运行中的数字

重点看：

- 已发现数量。
- 已完成正文数量。
- 剩余数量。
- 时间已归一化数量。
- 已提取投递信息数量。
- 已生成草稿数量。
- 质量通过数量。

日志区会实时显示当前步骤。日志自动滚动；需要看旧日志时可以暂停滚动或手动向上查看。

覆盖率区域还会汇总发现数量、正文尝试/成功数量、日期归一化数量、投递信息数量、草稿数量和质量通过数量。质量门禁状态会单独显示；失败原因和缺失原因会保留，不会用猜测内容填充统计。

### 10.3 终止和继续

- **终止任务**：停止新操作，保留已经完成的结果和检查点。
- **从检查点续跑**：继续未完成任务。
- **从检查点重试**：对失败任务重新执行失败部分。

任务状态可能是：待开始、进行中、已完成、未完成·可续跑、执行失败、已取消或已中断。看到“未完成”不代表已有结果丢失，先查看失败原因和恢复按钮。

## 11. 第九步：安全验证、限流和失败恢复

### 11.1 出现安全验证

当页面出现安全验证等待区：

1. 点击“打开验证页”。
2. 在浏览器中完成验证。
3. 回到控制台。
4. 点击“我已完成验证，刷新状态”。
5. 如果按钮显示“刷新并继续”，点击它恢复任务。

验证期间会暂停新的访问，已有检查点会保留。不要关闭浏览器，也不要在验证等待时反复启动新任务。

### 11.2 出现限流

当页面出现限流面板：

1. 点击“打开 APP 检查页”。
2. 在浏览器中确认页面能够正常加载。
3. 等待系统显示检查点已准备好。
4. 点击“我已确认恢复，续跑”。

限流状态下不会继续发起新的访问。恢复前先确认目标页面可用，不要直接刷新并重新启动全流程。

### 11.3 任务失败或未完成

1. 先看任务面板的失败原因。
2. 再看日志区最后一条错误。
3. 检查 Relay、AI、网络、候选人资料和邮箱配置。
4. 修正配置后点击“从检查点重试”或“从检查点续跑”。
5. 不要直接删除任务目录或清空浏览器数据。

如果只有某些结果缺少正文、日期、岗位要求或投递方式，结果仍会保留，并在卡片上标注“信息未完整”。

## 12. 第十步：查看和筛选结果

结果区是任务完成后最常用的区域。

### 12.1 顶部统计和筛选

结果区会显示：

- 全部结果。
- 已筛选结果。
- 信息不完整结果。
- 含图片结果。
- 未知日期结果。

可以设置：

- 排序：最新或最早。
- 时间：全部、24 小时、3 天、7 天、30 天、90 天、未知日期。
- 重置：清除当前筛选。
- 分页：每页 20 条，使用上一页和下一页。

如果当前草稿有未保存修改，切换分页、筛选或补全前，页面会提醒先保存。

### 12.2 一键智能补全

1. 找到“一键智能补全”。
2. 如果有未保存草稿，先点击“保存修改”。
3. 点击补全按钮。
4. 系统读取真实任务状态，从检查点补齐缺失字段。
5. 点击“查看补全进度”查看当前状态。

补全不会凭空制造岗位内容；无法确认的字段会继续标记缺失，并保留缺失原因。

### 12.3 结果卡片

每张卡片可能显示：

- 图片或视频封面预览。
- 标题。
- 发布时间。
- AI 分数。
- 处理状态。
- 投递路线。

常见状态包括：

- `已发送`：已完成发送动作。
- `>=90`：质量分数达到发送门槛。
- `信息未完整`：有字段缺失。
- `AI 失败·有初稿`：AI 后续步骤失败，但已有初稿。
- `待重写`：需要重新生成或手动修改。

点击卡片可以进入详情。点击“打开原文”会打开原始 APP_URL。

## 13. 详情页的每个功能

### 13.1 图片和 OCR

详情页可能显示多张图片，并标注来源：详情图、卡片图或封面图。

1. 点击图片进入预览。
2. 用上一张、下一张或缩略图切换。
3. 查看图片分析摘要。
4. 查看岗位信号。
5. 查看 OCR 可见文字。
6. 点击复制按钮复制图片文字。

图片内容只作为提取证据。看不清、无法确认或没有证据的内容会被标记为不确定。

### 13.2 岗位事实和投递方式

详情页会分组展示：

- 岗位职责。
- 岗位要求。
- 关键能力。
- AI 提取并复核的投递方式。
- 原始采集正文。

投递方式可能是邮件、私信、链接或其他方式。每条信息会尽量显示验证标签、证据、置信度和图片来源。只有可操作链接才会显示为可点击链接。

### 13.3 信息不完整和岗位补全

如果详情页显示信息不完整：

1. 先看缺少哪些字段。
2. 点击“一键补全全部缺失岗位”。
3. 等待补全任务结束。
4. 重新打开详情核对结果。

仍然缺失的字段不要手工编造。可以在草稿中补充本人确认过的信息，或保留为空并转人工核对。

## 14. 修改、保存和复制文案

详情页有三个主要编辑区：

### 14.1 私信

1. 在私信文本框中修改内容。
2. 点击私信旁的复制按钮。
3. 粘贴到 APP 对话框中。
4. 发送动作由你在 APP 中确认。

### 14.2 邮件

1. 修改邮件主题。
2. 修改邮件正文。
3. 使用复制按钮复制主题或正文。
4. 检查收件人、岗位名称和候选人信息。

### 14.3 求职信

1. 在求职信文本框中修改。
2. 检查事实、岗位称呼和联系方式。
3. 点击复制按钮，或先保存后发送邮件。

### 14.4 保存规则

- 点击“保存修改”后，页面显示“已保存”。
- 未保存时不要切换结果、分页或启动补全。
- 重新生成或补全可能覆盖旧草稿，因此重要修改必须先保存。
- 生成失败但已有初稿时，先保存初稿，再重新尝试。

## 15. 质量门禁和发送邮件

### 15.1 质量评分

详情页会显示：

- 总分/100。
- 重写次数。
- 通过提示或问题列表。

默认质量门槛是 `90` 分。低于门槛时：

1. 阅读问题列表。
2. 手工修改文案，或点击重新生成。
3. 保存修改。
4. 重新检查评分。

### 15.2 发送邮件

发送前逐项检查：

1. 质量分数达到 `90` 分。
2. 收件邮箱是从真实投递信息中提取的有效地址。
3. SMTP 已配置并测试通过。
4. 邮件主题、正文、求职信和候选人信息正确。
5. 已保存最新修改。

然后点击“发送邮件”。发送区会显示收件人、SMTP 状态和发送结果。发送是明确的手动动作，不会因为任务完成而自动群发。

### 15.3 其他交付按钮

- **复制私信**：复制已保存的私信草稿。
- **打开岗位**：打开原始岗位页面。
- **打开原文**：打开原始内容链接。

如果发送按钮是灰色，按顺序检查质量分数、收件邮箱、SMTP 测试状态和是否有未保存草稿。

## 16. 历史记录

顶部“历史”或页面下方的历史面板可以查看以前的任务。

1. 点击刷新按钮获取最新任务列表。
2. 表格会显示状态、关键词、北京时间创建时间、采集范围和产物数量。
3. 点击某一行查看任务。
4. 有检查点时，使用“从检查点续跑”或“从检查点重试”。
5. 没有检查点时，直接查看结果。

历史任务不要和新任务混用关键词、候选人资料或发件邮箱。开始新任务前确认当前选中的任务名称和时间。

## 17. 产物下载

顶部“产物”或产物面板会列出当前任务生成的文件：

- `application_intelligence.json`：岗位和投递信息的结构化结果。
- `application_intelligence.csv`：便于表格查看的结果。
- `application_intelligence.xlsx`：便于进一步整理的工作簿。
- `workflow-summary.json`：任务总体摘要。
- `parallel-body-summary.json`：正文处理摘要。
- `artifact-manifest.json`：产物清单和校验信息。
- `xiaohongshu_cards_latest.json`：最近一次卡片抓取结果。
- `xiaohongshu_notes_latest.json`：最近一次正文抓取结果。
- `delivery-state.json`：邮件或其他交付状态。

点击文件名或下载按钮保存产物。下载后建议保留任务关键词、时间和产物清单，方便追溯。

如果启用了“跳过结构化导出”，只会保留原始抓取结果，不要把缺少 XLSX/CSV 误认为任务失败。

## 18. 常见问题速查

| 现象 | 处理顺序 |
| --- | --- |
| 网页打不开 | 确认启动命令窗口仍在运行；访问 `http://127.0.0.1:4317`；检查端口是否被其他程序占用 |
| 页面显示 Relay 待配置 | 填端口和 Profile，点击“保存并启动 Relay” |
| Relay 已启动但未连接 | 打开登录页，打开目标页，完成登录，再点“检测连接” |
| 登录后仍识别不到 | 确认登录发生在项目管理的浏览器 Profile，而不是另一个普通窗口 |
| 没有目标标签页 | 点击“打开登录页”或“再开一个目标页” |
| AI 没有模型 | 点击“检测模型”；本地模型先安装并启用；远程模型检查 URL、Key、协议 |
| 启动按钮灰色 | 补齐 AI、关键词、姓名、学校、专业和邮箱 |
| 速度参数报错 | 确认最小间隔不大于最大间隔 |
| 结果缺正文 | 查看日志和检查点，修正 Relay/登录状态后续跑；不要编造正文 |
| 出现安全验证 | 打开验证页，人工完成后点击刷新并继续 |
| 出现限流 | 打开检查页确认可访问，等待检查点后点击确认恢复并续跑 |
| SMTP 测试失败 | 使用客户端授权码；检查 SMTP 主机、端口、SSL/TLS、STARTTLS 和防火墙 |
| 发送邮件按钮灰色 | 检查分数是否达到 90、收件人是否有效、SMTP 是否通过测试 |
| 切换结果提示未保存 | 点击“保存修改”，再切换分页或筛选 |
| 产物数量为 0 | 等任务完成或检查点结束；确认没有开启“跳过结构化导出” |
| 重启后需要重新登录 | 检查 `data/browser` 是否保留，确认没有更换 Profile |

## 19. 数据和隐私注意事项

- 浏览器 Cookie、登录会话和任务检查点保存在本机。
- API Key、邮箱密码、授权码和 OAuth2 Token 只放在本机配置中。
- 不要把 `.env`、`data/`、浏览器用户目录或带密钥的日志提交到仓库。
- 上传背景资料前先删除不需要的身份证号、密码和内部密钥。
- 发送邮件前必须人工核对收件人和正文。
- 复制私信后由人工在 APP 中确认发送。
- 原始 PDF、DOCX 和 TXT 不会被教程中的流程修改；需要修改时另存副本。
- 结果缺失时保留缺失状态，不用猜测补齐。

## 20. 开发者验证和排障命令

### 20.1 只检查本机 Relay

```powershell
node scripts/start-managed-browser.mjs --port 18800 --profile openclaw --data-dir data/browser --check-only
```

看到 `backend: native-cdp` 或现有 CDP 后端，以及 `running`、`cdpReady` 等成功状态，说明本机浏览器连接基础正常。

### 20.2 项目检查

```powershell
npm run check
npm run preflight
npm run verify:artifacts
```

也可以分开执行：

```powershell
npm test
npm run build
npm run test:python
npm run test:agents
```

### 20.3 开发模式端口

前端默认使用 `4317`，Relay 默认使用 `18800`。端口被占用时，先找到占用进程，再让前端、后端、Relay 和控制台使用一致的新端口。不要只改页面中的一个端口。

## 22. 推荐的日常使用顺序

日常重复使用时按下面 8 步即可：

1. 启动网页控制台。
2. 检查 Relay 和浏览器登录状态。
3. 检查 AI 会话和候选人资料。
4. 填写新的关键词和范围。
5. 点击“仅检查链路”。
6. 点击“启动全流程”。
7. 处理安全验证、限流或失败检查点。
8. 核对结果、保存文案、发送或下载产物。

遇到任何异常，优先保留当前任务、日志和检查点，再修正配置并续跑。这样可以避免重复访问和重复生成。
