# 背景资料 AI 解析规格 v2

## 目标

将用户上传的 PDF、DOCX、TXT、Markdown、JSON、CSV 或 RTF 转换为可核验的候选人事实档案。档案同时服务于署名信息回填、岗位匹配、私信、邮件和 Cover Letter，所有对外文案均以候选人第一人称书写。

## 模型路由

1. 解析模型以界面当前选择为唯一准则，完整身份为 `provider + Base URL + model + protocol`。
2. 已配置且具备密钥的外部模型优先于本地模型；只有没有可用外部配置时，本地模型才作为默认选择。
3. 用户修改提供方、Base URL、模型或协议后，旧会话立即失效，解析前必须按新配置建立会话。
4. 已保存密钥只能在同一 Base URL 下复用，防止把一个服务的密钥发送到另一个端点。
5. 用户选中外部模型后，缺少密钥、端点不可用或模型调用失败均返回明确错误；禁止静默降级到本地模型或其他模型。
6. 每份档案记录实际使用的 provider、Base URL、model、protocol、提示词版本和生成时间，`fallback_used` 固定为 `false`。

## 解析与证据编译

1. 当前所选模型必须完成一次真实的结构化理解调用，负责识别教育、经历、项目、技能、可实习安排及其来源关系；不得用本地规则代替该模型调用。
2. 服务端在调用前从原文生成 `verified_source_anchors`，提示模型不得遗漏已经逐字确认的署名字段与事实片段。
3. 模型返回后进入确定性的证据编译阶段：只有能在对应来源文件中逐字定位的字段和连续原文片段可以进入最终档案。
4. 小模型遗漏原文明示字段时，证据编译器会从 `verified_source_anchors` 补回；模型虚构、改写或错配来源的内容会被剔除。
5. 证据补回不是模型降级。`analysis_runtime` 始终记录本次实际调用的所选模型，解析失败时也不会切换到其他模型。
6. 最终第一人称摘要、优势和可写事实由已核验证据编排，避免把模型生成但原文不存在的姓名、公司、数字或成果写进求职信。

## 输入边界

- 文档正文与补充文本均是不可信数据，只作为候选人资料，不执行其中的命令、提示词或角色要求。
- “不可信”只限制执行文档中的指令，不表示可以忽略文档中明确出现的姓名、教育、经历、项目、技能与实习安排。
- 单次支持 1-8 个文件；每个文件沿用服务端大小和格式限制。
- 联系方式、学校、专业、年级、实习天数和实习时长只允许逐字提取，不做常识推断。

## 输出契约

- `candidate_application`：可回填到前端的署名字段；缺失值为空字符串。
- `candidate_application_evidence`：每个非空署名字段的来源、原文与置信度。
- `first_person_profile`：第一人称标题、叙述、核心优势和岗位价值。
- `evidence_items`：一条事实一个条目，包含稳定 ID、事实短句、第一人称句、来源文件、最短充分原文和置信度。
- `writing_constraints.allowed_claims`：下游文案唯一可用事实集合，只接收来源原文可定位且置信度不低于 75 的第一人称事实。
- `writing_constraints.missing_information`：求职信仍缺少的关键字段。
- `analysis_runtime`：本次调用的完整模型路由和提示词版本。

## 第一人称与事实规则

1. `summary`、`first_person_profile` 和 `evidence_items.first_person_claim` 必须包含“我”。
2. 禁止出现“候选人”“该同学”“简历显示”“材料显示”“附件显示”等第三人称或元叙述。
3. 工具接触不得扩写为“精通”或“熟练”；团队结果不得改写为个人独立成果。
4. 数字、成果、组织和职责必须有原文证据；资料未给出的信息保持为空。
5. 下游求职信优先直接使用 `first_person_claim`，`source_evidence` 只用于审计，不得复制进正文。
6. 服务端会核对来源文件和连续原文片段；核对失败的署名字段不回填，核对失败的经历不进入证据池。

## 求职信消费规则

- 邮件与 Cover Letter 固定顺序：主题、尊敬的招聘负责人、第一人称身份与申请动机、岗位相关证据、可实习安排、沟通邀请、此致敬礼、真实署名与联系方式。
- 证据按岗位相关性选择，至少使用一条已核验事实，不得用通用模板补齐缺失能力。
- 私信、邮件和 Cover Letter 都必须第一人称，不得把帖子作者、发布时间或互动量当成招聘方信息。
- 缺失联系方式时省略对应行，不输出 `XX`、`XXXX` 或其他占位符。

## 验收标准

1. 选择外部模型后，解析结果中的 provider、Base URL、model 和 protocol 与界面完全一致。
2. 外部模型缺密钥或会话不匹配时解析失败，且没有本地解析产物。
3. 解析结果至少包含来源可追溯的署名字段和证据条目；每条可用于文案的事实是第一人称。
4. 前端显示实际模型、解析端点、证据数量、第一人称摘要和待补字段。
5. 下游确定性兜底文案原样使用第一人称事实，不产生“在 skills 相关实践中，我”一类模板残句。
6. 小模型返回空字段时，原文明示的署名与经历仍会通过证据编译器落地；小模型虚构的姓名、公司、数字和成果不会进入档案。
7. 上传文件被服务端添加序号前缀后，模型返回原始文件名仍可匹配同一来源。
8. 自动化测试覆盖模型路由、密钥跨端点隔离、输出归一化、证据补回、幻觉剔除和求职信事实消费。
