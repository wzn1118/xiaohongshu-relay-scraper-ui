# 产品能力与优势说明

## 1. 不是单点工具，而是完整求职操作链

常见工具只覆盖搜索、收藏、写作或发邮件中的一个环节。本项目把岗位发现、帖子取证、任务恢复、事实整理、简历匹配、文案编辑、标题校验、人工审核、邮件发送、历史复盘和面试研究串在同一任务中。用户不必在多个工具间反复搬运原帖、岗位要求和个人经历。

**价值边界：**这一优势来自系统工作流和数据契约，不代表系统替用户决定是否投递，也不承诺面试结果。

## 2. 先判断机会，再投入写作时间

系统优先展示发布时间、正文完整度、招聘状态、岗位事实、联系方式和投递路径。用户可以先淘汰过期、信息缺失或入口不清的帖子，再生成材料，减少“文案写到一半才发现岗位失效”的浪费。

## 3. 采集结果可恢复、可追溯

- 任务、检查点和产物以 Task ID 组织；
- 中断后从已保存状态续跑；
- 卡片、正文、图片、评论和分析产物保留来源关系；
- 前端区分正在运行、部分完成、失败、可恢复和完成；
- 文件页提供实际产物下载，不把 UI 数量当作落盘证据。

这比“失败后重新搜一遍”更适合长时间、易受登录验证和网络波动影响的采集任务。

## 4. 文案围绕真实事实，不只追求语言流畅

文案流程先读取岗位要求，再从用户确认的教育、项目、经历、技能和成果中匹配证据。质量门检查未被事实支持的声明、岗位匹配、称呼、时间、联系人、标题规则和附件要求。用户仍可以编辑邮件正文和 Cover Letter，系统保留草稿版本。

## 5. 邮件标题是正式草稿的一部分

很多团队直招帖子会明确邮件主题或附件命名。本项目把标题规则作为结构化字段，不把它埋在正文里：

- 从正文要求和附件要求推导标题；
- 在“编辑正文”中同时编辑标题、正文和 Cover Letter；
- 保存后更新发送预览；
- 标题变化会使旧预演失效；
- 发送前再次按岗位要求校验。

## 6. 批量能力带有人控门禁

批量投递不是点击一次立即发送。流程分为：

1. 选择候选项；
2. 运行投递预演；
3. 检查收件人、标题、正文和附件；
4. 冻结待发送内容；
5. 审核批次；
6. 用户点击开始发送。

任何正文或标题编辑都会让冻结内容失效，避免“页面看到的是新版、实际发送的是旧版”。

## 7. 公网 UI 与本地能力可以组合

应用可以通过 HTTPS 公网访问，但敏感执行面仍留在源站机器：

- 托管浏览器和 Cookie 留在本机；
- 本机模型端口不暴露公网；
- 公网请求通过服务端 AI Session 调用本机模型；
- MCP 和 CDP 只监听回环地址；
- API Key 和 SMTP 凭据不进入浏览器产物或公共包。

这使用户可以远程使用统一 UI，同时保留本地浏览器、模型和数据边界。

## 8. Data Copilot 面向“下一步做什么”

采集几十条结果以后，用户的问题从“有没有数据”变成“哪些更适合我”。Data Copilot 可以在用户选择的岗位、正文、评论、面经和个人材料范围内进行比较、总结和排序，并保留引用和原帖入口。它不是脱离资料的通用聊天窗口，而是当前任务数据上的决策辅助层。

## 9. MCP 接入不是裸露全权限接口

MCP 使用上下文绑定 Grant，而不是给客户端永久全局令牌。Grant 限制：

- 可用工具和资源；
- Read/Write/Approval Required 风险上限；
- 有效期、调用频率和并发数；
- 资源快照和上下文 Hash；
- 高风险动作人工审批；
- Idempotency、防重复执行和审计记录。

这使外部 Agent 可以复用项目能力，同时减少越权和上下文漂移。

## 10. 面向真实运行的工程能力

- 一键本地启动和生产启动；
- 无开发环境机器所需的便携 Node、Python、cloudflared 和 Chromium；
- 端口占用检查与自动选择；
- 生产进程状态、看门狗和开机启动；
- 备份、恢复预演、哈希清单和 MCP Grant 撤销；
- 公共发布包凭据排除和归档扫描；
- Node、Python、API、MCP、前端构建和 Playwright 测试入口。

## 11. 用户界面按任务顺序组织

左侧导航对应用户自然操作顺序，右侧只展示当前模块。用户不需要在一个超长页面中同时理解环境、任务、结果、投递和文件。默认展示任务有固定 ID，历史任务可从“历史”进入并自动切换到对应工作区。

## 12. 适用范围

适合：

- 从内容社区寻找实习、校招、团队直招信息；
- 需要批量保存正文、图片、评论和投递入口；
- 希望以自己的简历事实生成和编辑投递材料；
- 需要断点续跑、可追溯产物和人工审核；
- 希望把本地模型或 MCP 工具接入公网工作台。

仍依赖外部条件：

- 目标站点账号和页面状态；
- 用户有权使用的模型接口或本机模型；
- 用户自己的邮箱发送授权；
- 用户自己的域名和 Cloudflare Tunnel；
- 对目标网站规则、数据使用和邮件发送责任的判断。
